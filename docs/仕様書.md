# 補給地点選定・配分ルート最適化 仕様書

使い方（GUI / CLI のコマンド、シナリオ JSON の項目）はリポジトリ直下の `README.md` を参照。
ここでは計算の前提・アルゴリズム・入出力の形を定める。

## 1. 概要

複数の目的地へ「機材＋人員のセット」を 1 か所 1 個ずつ届けるとき、

1. **補給地点の選定**（`depot_planner/solver.py`）… 候補から K か所を採用し、各拠点に置く機材の数を決める
2. **配分ルート最適化**（`depot_planner/routing.py`）… 車両 1 台に積める機材の数（積載量 C）を踏まえ、各車両の順路を決める

の 2 段で計算する。どちらも「最も遅い車両の所要時間（メイクスパン）」の最小化が目的。
2 は省略できる（`params.routing.enabled = false`）。

- 言語 / 実行環境: Python 3.12 以上、`uv`
- 主要依存: `ortools`（ルート最適化）、`numpy`（選定の総当たり）、`fastapi` / `uvicorn`（GUI）、`python-docx`（報告書）
- 外部 API: Mapbox Matrix API / Search Box API（所要時間・地点検索）。OSRM 公開デモサーバへのフォールバック可

## 2. 所要時間（`travel_times.py`）

- `build_matrix(sources, destinations)` が `matrix[i][j]` = 地点 i → 地点 j の道路上の所要時間[分] を返す。
- キャッシュ `cache/travel_times.json` は「取得元|プロファイル」ごとに座標ペア単位で持ち、足りないペアだけ取得する。
- 到達不能ペアは `UNREACHABLE = 1e9`。どの候補からも到達できない目的地があれば実行前にエラー。

## 3. 補給地点の選定（`solver.py`）

- コスト: `cost[i][j] = 積込 + 移動(候補 i → 目的地 j) + 作業`（各目的地へ直行する前提）。
- 拠点あたりの上限はないので、拠点集合を決めれば「各目的地を最寄り拠点へ」が最適な割当になる。
  問題は K 拠点の選び方だけに帰着する（施設配置問題の p-center / p-median）。
- 目的関数 `objective`: `makespan`（最大値 → 同点は合計）/ `total`（合計 → 同点は最大値）。
- 探索: 組合せ数 ≦ `max_exact_combinations` なら numpy で全組合せを総当たり（厳密解）。
  超える場合は貪欲法 + 1 対 1 入替えの局所探索（近似解）。
- `status = required` の候補は必ず採用、`excluded` は選定対象から外す。
- 各採用拠点の **機材数（stock）** = 担当する目的地の数。合計は目的地数と一致する。
- 感度分析: 採用数 K を範囲で変えて同じ計算を繰り返す（選定のみ。ルート最適化は本計算の K だけ）。

## 4. 配分ルート最適化（`routing.py`）

### 前提
- 1 台に積める機材は `vehicle_capacity`（C）個まで。
- 採用拠点 i には `ceil(stock_i / C)` 台の車両が待機する（機材を 1 回で積み切れる台数）。C=1 なら 1 目的地 1 台。
- 車両は「補給地点で最大 C 個積む → 順に配る → 補給地点へ戻って積み直す」を繰り返せる。
  1 台の配送件数の上限は `max_deliveries`（`null` = C と同じ。つまり既定では積み直さない）。
- 車両と補給地点の所属は固定しない。在庫が残っていればどの拠点から積んでもよい。
- 所要時間 = 移動 + 目的地での作業 `service_min` + 積込 `reload_min`（機材 1 個ごと）。補給地点への帰路は含めない。

### OR-Tools へのモデル化
| ノード | demand | 備考 |
|---|---|---|
| 目的地 | −1 | 必須訪問 |
| 積込ノード（在庫 1 個 = 1 ノード） | +1 | 任意訪問（`AddDisjunction` penalty 0）。ノード数で在庫上限を保証 |
| 出発ノード（車両ごと） | 0 | 待機拠点の位置 |
| garage | 0 | 全車両共通の終点。出入りの時間は 0 |

- **Time 次元**: アークコスト = 所要時間（0.01 分単位で整数化）。`SetGlobalSpanCostCoefficient(10000)` でメイクスパンを強く最小化。
- **Load 次元**: 容量 C。積まずに配る・C 個を超えて積む、を禁止する。
- **Deliveries 次元**: 1 台あたりの配送件数 ≦ `max_deliveries`。
- **初期解**: 各車両が待機拠点で積めるだけ積み、近い目的地から配る自明解を種として与える（制約が厳しいと構築ヒューリスティクスが解を作れないため）。
- **探索**: `PATH_CHEAPEST_ARC` → `GUIDED_LOCAL_SEARCH`、`time_limit_sec` で打ち切り。改善解が出るたびに進捗を報告し、中止要求があれば探索を止める。

### 注意
- 選定は直行前提で行うため、C ≧ 2 では選定時点のメイクスパンは参考値。実際の所要時間はルート最適化の結果を見る。
- 時間制限つきの局所探索なので厳密な最適とは限らない。

## 5. 出力（`runner.run_scenario()` の戻り値）

```python
{
  "scenario_name", "run_at", "elapsed_sec", "provider", "fetched_pairs", "params",
  "summary": {
    "makespan_min", "total_min", "avg_min",      # 選定段階(直行前提)
    "num_targets", "num_vehicles", "vehicle_capacity",
    "num_depots", "num_candidates", "num_excluded", "method", "combinations",
    "lower_bound_min", "bottleneck_target",
  },
  "depots":      [{"id", "name", "lat", "lon", "stock", "vehicles", "max_min", "targets", ...}],
  "assignments": [{"target_id", "target", "depot_id", "depot", "travel_min", "time_min", ...}],
  "candidates":  [{"id", "name", "status", "result", ...}],
  "sensitivity": [{"k", "makespan_min", "total_min", "depots": [{"id", "name", "stock", "vehicles"}]}],
  "routing": {                                    # ルート最適化をしないときは None
    "vehicle_capacity", "max_deliveries", "num_vehicles",
    "makespan_min", "total_min", "time_limit_sec", "elapsed_sec",
    "vehicles": [{
      "no", "start_id", "start", "start_lat", "start_lon", "time_min", "deliveries",
      "stops": [{"kind": "pickup" | "deliver", "id", "name", "lat", "lon",
                 "count",        # pickup のみ。同じ拠点での連続積込をまとめた個数
                 "done_min"}],   # その立ち寄りでの作業(積込)完了時刻[分]
    }],
  },
  "warnings": [str, ...],
}
```

保存物（`runs/<日時_名前>/`）: `result.json`、`assignments.csv`、`routes.csv`（1 行 = 1 立ち寄り）、`report.docx`。
CSV は Excel で開けるよう BOM 付き UTF-8。
