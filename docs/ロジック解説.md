# 人員配置ルート最適化 ― ロジック解説（初心者向け）

このプロジェクトは「**たくさんの地点へ、機材と測定人のセットを最速で配り終えるには、車をどう走らせればいいか**」を計算するプログラムです。
このドキュメントは、プログラミング初心者でも全体像がわかるように、やさしく説明します。

---

## 1. そもそも何をしたいの？

地図上に **配り先（経由地）** がたくさんあります。
そこへ「機材＋測定する人」のセットを **1地点につき1個ずつ** 届けたい。

セットは **補給地点（デポ）** に置いてあります。
車はそこでセットを積んで、配り先まで運びます。

ゴールはシンプルで、

> **全部配り終わるまでの時間を、できるだけ短くする**

ことです。一番遅い車が終わった時刻が「全体の完了時刻」になるので、それを縮めます。
この「全部終わるまでの時間」を専門用語で **メイクスパン** と呼びます。

---

## 2. 大事なルール（制約）

現実に合わせて、いくつかルールがあります。

1. **車は1回に1セットしか運べない**
   → 「補給地点で1個積む → 1地点に配る → また補給地点に戻って積む」をくり返します。
   （トラックではなく、1セットだけ運ぶイメージ）

2. **補給地点には在庫（stock）の上限がある**
   → 例：補給1は6個まで、補給4は5個まで…。在庫を超えて積むことはできません。

3. **車と補給地点に決まった担当はない**
   → どの車も、在庫が残っていればどの補給地点から積んでもOK。
   「この車は補給1専用」みたいな決めつけはしません。

4. **車の台数は自由**
   → 補給地点が4つでも、車は6台使ってもかまいません。台数が多いほど並行して配れるので速くなります。

---

## 4. データの形（`waypoints.py`）

### 配り先（経由地）

1地点はこんな形のデータです。

```python
{"id": 1, "name": "1", "lat": 36.2203, "lon": 139.4971, "group": 1}
```

- `lat` / `lon`：緯度・経度（地図上の位置）
- `group`：グループ分け（今回は `group == 1` の地点だけを配り先にしています）

### 補給地点（デポ）

```python
{"id": 1, "name": "補給1", "lat": 36.1866, "lon": 139.5126, "stock": 6}
```

- `stock`：その補給地点が持っているセットの在庫数

---

## 5. 計算の流れ（`main.py` → `distribute_solver.py`）

`main.py` を実行すると、次の順に処理が進みます。

```
① データを用意する        （配り先リスト・補給地点リストを作る）
② ソルバーに渡す          （solve_distribution を呼ぶ）
③ 最適なルートが返ってくる
④ 結果を画面に表示する
```

計算の本体 `solve_distribution()` の中は、目的ごとに **8つの部品** に分かれています。

| 順番 | 部品の名前 | やっていること（やさしく言うと） |
|------|-----------|--------------------------------|
| 1 | `check_stock` | 在庫が配り先の数より足りているか確認 |
| 2 | `build_node_model` | 地図上の場所を、計算しやすい「番号付きの点」に並べ替える |
| 3 | RoutingModel構築 | 車を「共通のスタート地点」から出発させる準備 |
| 4 | `add_time_dimension` | 移動時間を計算し、「最速にする」目標を設定 |
| 5 | `add_capacity_dimension` | 「1回1セットだけ」のルールを設定 |
| 6 | `add_pickup_options` | 「どの補給地点を使うかは自由」を設定 |
| 7 | `build_search_params` | 答えの探し方（アルゴリズム）を設定 |
| 8 | `extract_solution` | 計算結果を、人が読める順路に翻訳 |

---

## 6. ここが肝心 ― どうやって「最適なルート」を見つけるの？

実は、このプログラムは **「ルートを自分で組み立てて」いません**。
代わりに、**「ルールと目標」だけを伝えて、専用の計算エンジン（Google OR-Tools）に解かせています。**

イメージはこうです。

> 「この点とこの点をつなげていい。ただし “1回1セット” と “在庫の上限” は守って。
>  その中で、一番時間がかかる車を一番短くして！」

とお願いするだけ。あとはエンジンが、つなぎ方の組み合わせを高速に試して、良い答えを見つけてくれます。

### どうやって試すの？（探し方）

1. **まず適当に1つ答えを作る**（近い点からつないでいく）
2. **少しずつ入れ替えて改善する**
   - 「この配り先を別の車に渡したら、全体が速くなる？」
   - 「順番を入れ替えたら短くなる？」
   を何千回も試す
3. **時間切れ（今回は15秒）になったら、その時点で一番良かった答えを返す**

なので、答えは「数学的に絶対の最適」ではなく「**短い時間で見つけた、とても良い答え**」です（規模が小さいのでほぼ最適になります）。

---

## 7. 「1回1セット」をどう守らせているか（仕組みのコツ）

ちょっとした工夫があります。

- **積載量** という数字を用意し、「補給地点で +1、配り先で −1」と変化させます。
- そして「積載量は **0か1まで**」というルールを置きます。

すると…

- 積んでいない（0）のに配り先へ行く → −1になってルール違反 → **禁止**
- 続けて2回積む → 2になってルール違反 → **禁止**

結果として、**必ず「補給 → 配る → 補給 → 配る…」の順番**でしか動けなくなります。
わざわざ複雑な命令を書かなくても、数字のルール1つで現実の動きを再現できる、というわけです。

### 在庫の上限も同じ発想

補給地点ごとに「積める場所（pickup）」を **在庫の数だけ用意**しておきます。
6個しか置かなければ、7回目は積む場所が無い → **自動的に在庫オーバーを防げます**。

## 8. 結果の読み方

実行するとこんな出力が出ます。

```
メイクスパン: 121.9 分

[車両0] 配送=4件 使用デポ=補給2 所要=119.8分
   補(補給2) -> 配[9] -> 補(補給2) -> 配[10] -> 補(補給2) -> 配[11] -> 補(補給2) -> 配[17]
```

- **メイクスパン**：全車が配り終わるまでの時間（これを最小化している）
- `[車両0]`：0番の車の話
- `配送=4件`：この車が配った地点の数
- `使用デポ=補給2`：結果としてこの車が使った補給地点
- `所要=119.8分`：この車が走り終えるまでの時間
- 下の行：実際の順路。`補(補給2)` ＝ 補給2で積む、`配[9]` ＝ 地点9へ配る

「使用デポ」は **最初から決めていたのではなく、計算の結果そうなった** だけ、という点がポイントです。

## 9. 動かし方

ターミナルで、プロジェクトのフォルダに移動して：

```bash
uv run main.py
```

これだけです。`uv` が必要な部品（ortools など）を自動でそろえて実行します。

### 設定を変えたいとき

`main.py` の中の、この部分の数字を変えます。

```python
result = solve_distribution(
    targets, depots, num_vehicles=6,   # ← 車の台数
    speed_kmph=40,                     # ← 平均速度（km/h）
    service_min=10,                    # ← 1地点での作業時間（分）
    reload_min=5,                      # ← 1回の積み込み時間（分）
    time_limit_sec=15)                 # ← 計算にかける秒数
```

例えば `num_vehicles` を増やすと、より多くの車で手分けして配るので、メイクスパンは短くなります。

## 10. いまの「割り切り」（今後よくできる点）

このプログラムは、わかりやすさ優先でいくつか簡略化しています。

1. **距離は直線距離**（実際の道路ではなく、地図上の最短距離で計算）
   → 本当は道路や渋滞を考えると変わる。将来 Google の経路APIに差し替え可能。
2. **速度は一律**（渋滞や信号は考えていない）
3. **車のスタート地点は自由**（どこから始めても時間ゼロという前提）
4. **答えは「とても良い近似」**（厳密な数学的最適とは限らない）

これらは、データやAPIを足していけば、後からより現実に近づけられます。

- やりたいこと：**全地点へ最速でセットを配る車のルートを決める**

- コツ：**「積載量0〜1」という数字のルールだけで、現実の動きを再現している**
